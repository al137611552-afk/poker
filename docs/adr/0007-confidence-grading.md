# ADR-0007：复盘打分的 A/B/C 置信度分级

- 日期：2026-08-21
- 状态：已采纳（判据可调，改之前先读「为什么不加权」那节）
- 相关：FR-9；ADR-0005（方案 B 的保真度上限）、ADR-0006（EV 口径）

## 背景

PRD 的原则是硬的：**非求解得出的建议必须标注置信度，不得冒充精确解**。

逐点 EV 损失已经算得出来（`review.py`），但同样一句「你亏了 2.3bb」，
可能是干净解上的确凿结论，也可能整个落在求解器自己的残差里。
**把这两种混在一张表里给人看，比不给更糟**——它会让人照着噪声改打法。

## 决策

三档，取**最差**的那条信号定级（`confidence.py`，纯逻辑）：

| 档 | 含义 | 判据 |
|---|---|---|
| A | 可据此改打法 | 下面两档一条都不沾 |
| B | 有保留 | 这手牌的牌类被聚合伤得重（类内落差超门槛）；或范围经过滚动聚合（转牌及以后）|
| C | 只能参考 | 英雄的牌不在假设范围里；或损失落在噪声底以内；或**噪声底量不到** |

**逐点定级，按场景给分布**（`ScenarioLeak.grades` = A/B/C 各多少个点）。
一格一个字母是骗人的：同一类局面里，有的点解得干净、有的整个落在残差里。

报告另给 **`confident_loss`**（只把 A 档的点加起来）。排序**仍用 `total_loss`**——
换掉它等于悄悄改了报告的语义；两个数并排放着，差得远就说明这一行的名次是
B/C 档撑起来的。

## 为什么不加权

置信度不是打分，是**「最弱的一环有多弱」**。加权会让「三个小毛病」平均成一个还不错的分数，
而实际上任何一条单独成立都足以让这个数不能用。理由要**全部**列出（不只是定级的那条），
读的人需要知道有几处不确定。

## 两条不肯让步的默认值

1. **「量不到」不许读成「很好」**。噪声底测不出来时给 C，不给 A。
   这是整个模块最容易被改坏的地方：`noise_floor is None` 时直接跳过检查、让它落到 A，
   代码更短、测试也照样绿——然后报告会**在最该示警的时候显得最干净**。
   与 `leaks.py` 里 `unconverged` / `ranking_trustworthy` 那两条同源。
2. **落在噪声里就是 C，哪怕别的都干净**。解自己还差 0.5bb 时，
   一个 0.3bb 的「漏洞」量的是求解器的残差，不是打法。

## 已知的空档

`hand_class_flagged` 与 `rolled_streets` 两个信号**目前恒为 0/False**，
因为当前复盘走的是一棵多层大树：转/河牌的范围是树里长出来的，**没经过按牌类聚合**，
所以传 0 是事实、不是乐观假设。等接上 `rollout.py`（方案 B：每街一棵小树 + 滚范围）
必须把真值传进去，否则那两档降级就白写了——`build_report` 里有注释钉着这一条。

## 已知代价

- 判据里的门槛（`SPREAD_THRESHOLD=0.35`）是拍的，没有实测支撑。
  它只影响 B 与 A 的边界，**不影响 C**（C 的两条判据都是可证伪的量）。
  要调就拿真实报告调，别拿直觉调。
- 分级让报告变长。这是有意的：短而自信的报告正是这条 FR 要避免的东西。
