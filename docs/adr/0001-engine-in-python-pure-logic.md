# ADR-0001：引擎层用 Python 实现，并强制纯逻辑

- 日期：2026-08-17
- 状态：已接受

## 背景

引擎是整个系统的地基：牌桌、bot、统计、复盘打分全部读它的输出。它同时有两个矛盾的
需求——**要绝对正确**（一处边池算错，所有统计与打分都不可信），又**要够快**
（后台自对弈要能批量生成牌谱）。

## 决策

1. 引擎层用 **Python** 实现，放在 `src/holdem`。
2. 强制**纯逻辑**：不碰 IO、不摸全局随机数，牌由调用方以「已洗好的一副牌」注入。
3. 求值器先用位运算的直写实现，不引第三方求值库。

## 理由

- 服务端选定 FastAPI（Python），引擎同语言可省掉一整层 FFI 与序列化，M0–M3 的迭代
  速度是主要矛盾。
- 纯逻辑让「(种子, 手数) 精确复现任意一手牌」成为可能，这是回放、复现、
  「同一副牌换个打法」三个功能的共同前提，也让单测不需要任何 mock。
- 不引求值库，是为了让 `tests/test_evaluator.py` 里的慢速参考实现能作为独立的
  交叉验证基准。将来换成查表或 Rust 实现时，这份基准就是验收标准。

## 实测

单核 Python，随机策略自对弈 1,000,000 手：**5,126 手/秒**（195 秒，平均 6.6 个动作/手），
全部不变量通过。按此推算，一夜（8 小时）单核可生成约 1.5 亿手，多进程还能再乘核心数。

## 结论

M0–M4 阶段吞吐够用。触发下沉到 Rust 的条件是：需要在线做深度受限搜索、
或自对弈吞吐成为训练瓶颈。届时用现有实现做交叉验证基准，逐模块替换，
`pots.py` 与 `evaluator.py` 因为是纯函数，替换成本最低。

## 已知限制

- Python 引擎不适合直接给树搜索当内循环（每节点都要 `clone()` 深拷贝）。
- 求值器是分支实现而非查表，单次约数微秒级；热路径替换时优先动它。
