# ADR-0009：ICM 口径的推弃解——以及它已知的偏差

- 日期：2026-08-25
- 状态：已采纳（**输出只适合看方向，不适合当开牌表照抄**，见「已知偏差」）
- 相关：FR-13；ADR-0003（推弃纳什求解）

## 背景

`pushfold.py` 解的是**筹码 EV** 口径的推弃均衡（可利用度 <1e-4，对得上公开纳什表）。
现金桌里那就够了——筹码就是钱。

**锦标赛不是。** 奖金按名次分，所以泡沫圈上「赢了多拿一点点、输了直接归零」。
筹码 EV 为正的全下，ICM 口径常常是负的。不做这个换算，短筹码在钱圈附近的建议全错。

## 决策

### 1. 把收益抽成 `Payoffs`，同一个 CFR 内核解两种口径

推弃只有七个终局（小盲弃 / 偷到 / 摊牌赢输，大盲弃 / 摊牌赢输）。
把它们抽成一个数据类，筹码口径是默认，ICM 口径由 `tournament.icm_push_fold_payoffs`
算出来传进去。CFR 内核一行没动。

**关键在于这七个数与牌类无关**——牌类只影响权益。所以 ICM 只在求解前算七次；
要是放进 CFR 内部，每步每类都要递归一遍 ICM，那是几十万次。

### 2. 等价性有测试守着

抽象之前先确认改造是**等价变换**：筹码口径下新公式化简回原式，
`test_pushfold.py` 的 14 项（含「对得上公开纳什表」）全绿才继续。

> 改造中途搞反过一处：`call_ev` 里的 `equity_sum` 是**按 hero 取行**的，
> 那里 hero 就是大盲，所以它已经是大盲自己的权益，不该再取补。
> 五条测试当场变红——**这就是先做等价变换、再加新功能的价值**。

## 实测：两个口径差多少

短筹码 1000（5bb）在小盲，对手 4000：

| 场景 | 筹码 EV | ICM |
|---|---|---|
| 泡沫圈（4 人剩 3 有奖） | 推 71.6% / 跟 62.1% | 推 64.5% / 跟 49.3% |
| 已进钱圈（3 人都有奖） | 推 71.6% / 跟 62.1% | **推 11.7% / 跟 9.2%** |

收益的不对称是根源：筹码口径赢 +5.0 / 输 −5.0（对称），
ICM 口径赢 +7.34 / 输 −9.09（**输得更多**）。

## ⚠ 已知偏差：这是**单手** ICM，系统性偏紧

上表第二行的 **11.7%** 紧得离谱，那不是解错了，是**模型本身的边界**：

单手 ICM 只问「这一手推还是不推」，**假定不打就没事**。
真实锦标赛里不打也在流血——盲注每圈都要交，5bb 熬不过几圈。
「反正保住第三名」的逻辑推到极端，就得到 11.7%。**照这个打会被盲注吃死。**

严肃工具（HoldemResources 那类）用的是**未来博弈**模型：把后续几手的盲注压力
一并算进去。我们没有那个，短期也不打算做（那是另一个量级的工程）。

**所以：输出适合用来看「方向」（ICM 比筹码口径紧多少、越接近钱圈越紧），
不适合直接当开牌表照抄。** 这句话写在函数文档里，并有测试钉着它不许被删。

## 已知代价

- Malmuth-Harville **假定筹码量就是全部信息**——不看位置、不看技术。
  两个筹码相同的人，会打的那个实际价值更高，ICM 看不出来。
- 推弃模型假设**桌上其他人这手不参与**，只交前注。多人同时入池的情况不在模型内。
- ICM 口径的可利用度单位是**奖金**，别拿它跟筹码口径的 bb/手比大小。
