# ADR-0008：翻后逐街范围收缩用「分位」，不用绝对牌力

- 日期：2026-08-21
- 状态：已采纳（参数待用批量对局校准）
- 相关：FR-11；ADR-0005（方案 B 的按牌类聚合上限）

## 背景

bot 翻后算权益走的是 `monte_carlo_equity(hole, board, opponents)`——
**对手手牌是从剩余牌里均匀抽的**，完全不看他翻前怎么打、翻后怎么打。
于是一个只在被 3bet 后才跟注的紧手，和一个见牌就跟的鱼，在 bot 眼里是同一个对手。

翻牌时的范围早就有了（`range_tracking.flop_ranges`，来自离线解好的翻前表），
缺的是**翻后每个动作之后怎么把它收窄**。

## 决策

### 1. 逐组合，不按牌类

`Range` 是 169 个牌类的粒度，翻前够用（翻前 `AhKh` 与 `AsKc` 确实等价），
**翻后完全不够**：两张红桃的面上，`AhKh` 是同花听牌而 `AsKc` 什么都不是。
按牌类收缩会把这两个当成一手牌，「他跟注了所以有听牌」这类推断整个失效。
故用 `ComboRange`（逐组合权重），并在展开时**排除与公共牌撞牌的组合**。

### 2. 判据是分位，不是绝对牌力

收缩判据是**这手牌在他自己当前范围里排第几**，不是「有没有成对」。理由是可证伪性：

- 绝对牌力要定一堆阈值，而「顶对算不算强」取决于牌面；
- 分位只需要一个排序，**天然随牌面自适应**——A 高牌在 `AKQ` 面上是弱牌、
  在 `722` 面上是强牌，同一套代码不用改。

各动作保留的比例（`KEEP_ON_BET=0.55` / `KEEP_ON_CALL=0.75` / `KEEP_ON_CHECK=1.0`）
**是拍的，没有实测支撑**。调它们要拿批量对局的 bb/100 调，别拿直觉调。

### 3. 过牌一点都不收

过牌几乎不含信息：强牌可以埋伏、弱牌可以放弃，两头都在。
收它等于凭空造出一个「他没牌」的结论——那是这类跟踪最常见的错误来源。

### 4. 再狠的收缩也至少留下最强的一手

保护就是 `max(1, round(len * share))` 那一行。空范围会让下游的权益计算除零，
或者更糟：悄悄给出一个看着正常的数。

> 写这条时先写了一段「收空就回退到不收缩」的兜底，然后发现有了 `max(1, ...)`
> 它**永远走不到**——留着等于假装有两层保护，实际只有一层。已删。
> 死掉的保护比没有保护更坏：它会让下一个人以为这里已经防住了。

### 5. 听牌折算成「相当于一对」（2026-08-21 补）

排序键从「只看成手」改成 `(有效档次, 原始分)`，有效档次＝成手与听牌折算取大的。
只认**强听牌**（同花听、开口顺）：卡顺与后门不算——把它们也抬上来等于几乎不收缩，
这个模块就没用了。河牌上折算自动消失（牌已发完，听牌不是牌力）。

折算到 `PAIR` 这一档**是拍的**：强听牌对一对约 35% 权益，比一对弱、比空气强得多，
落在这一档最接近。要调用批量对局的 bb/100 调。

识别用位运算，**不遍历补牌**：`evaluate` 一次 4.5µs，一个决策里几百个组合各数一遍
补牌是几万次调用（约 60ms/决策），bot 实时用不起。

## 已知局限

折算档次没有实测支撑，`ComboRange.confidence` 会如实说出这一点（PRD 的「诚实」那条）。

## 验收结果（2026-08-22，2 万手 × 2 组）

同桌直接对抗（一半座位开、一半不开，风格相同、按钮逐手轮转）：

| | bb/100 | ±95% | WTSD | W$SD |
|---|---|---|---|---|
| 范围感知 | **+306** | ±216 | 41–46% | 60–66% |
| 随机牌口径 | −306 | ±264 | 63–66% | 40–44% |

翻前统计两组**一模一样**（VPIP 17–19%、PFR 14%）——翻前没动，差异全在翻后。

### 排除「只是变紧了」这个替代解释

范围口径的权益系统性低于随机口径（`KQo` 在 `Qs7h2c` 上：87.7% → 15.4%），
所以 bot 会整体变紧。**赢的会不会只是「紧」而不是「准」？**

对照实验：把对手换成更紧的 `nit` 风格（仍用随机口径）。结果是
**nit 的 WTSD 还是 63–65%，跟 tag 一模一样**——
**风格参数根本控制不了翻后的跟注松紧**（它只管翻前）。
43% 那个 WTSD 是调风格达不到的，所以差距不能归给「变紧」。
（差距从 +612 收窄到 +272，收窄的那部分是 nit 翻前更紧少输的，方向与显著性不变。）

### 这个数**不能**读成「范围跟踪值 300 bb/100」

两组的 WTSD 都远高于真实扑克的 25–30%，**基线 bot 翻后本来就是个重度跟注站**。
这个 A/B 量到的是「修好了一个明显缺陷」，不是这套跟踪本身的价值上限。
换一个翻后不那么松的基线重测，差距一定小得多。

**结论：默认打开**（`Bot(range_aware=True)`）。覆盖率 86%——
其余 14% 落在多人底池、翻前线路表外或范围被撞光，自动退回随机口径。

## 校准结果（2026-08-22，两个种子 × 25000 手 × 4 组）

扫 `KEEP_ON_BET`，同种子配对比较（牌一样，差异只来自决策）：

| bet | 种子 A | 种子 B | WTSD（A / B） |
|---|---|---|---|
| 0.35 | 177.6 | 106.9 | 35.5% / 36.6% |
| **0.55（默认）** | 320.1 | **382.7** | 41.2% / 42.6% |
| 0.80 | **352.6** | 337.2 | 53.6% / 55.7% |
| 1.00（完全不收缩） | 188.3 | 168.5 | 65.3% / 66.2% |

### 结论一：收缩确实有用，形状可信

两个种子下**两端都明显低、中间高**（倒 U）。`1.00` 那一组是关键对照——
它等于「只用翻前范围、逐街完全不收缩」，两次都明显差于中间——
所以**「价值全在用范围代替随机牌、收缩纯属白干」这个假设被排除了**。
形状重现比单调趋势更难用噪声解释：噪声不会系统性地造出倒 U。

### 结论二：峰值位置分不出来，**所以不改默认值**

A 峰在 0.80、B 峰在 0.55，互相之间的差都在噪声内（单座 95% 半宽约 210）。
0.55 与 0.80 之间是一片**平台**，当前默认就在平台里。
再加手数去区分它俩，边际价值很低——两者的真实差距可能本来就很小。

### 结论三（最有用的一条）：调这类参数该盯机制指标，不该盯 bb/100

**WTSD 在两个种子下几乎完全一致**（如 0.80 组：53.6% vs 55.7%），
而同一组的 bb/100 差了上百。bb/100 是结果指标，被单手盈亏的方差主导；
WTSD 是机制指标，直接反映参数在做什么。

**而且 bb/100 这个目标本身就选错了。** 这些 bot 的对手池是随机口径的跟注站
（WTSD 63%+），对着一个有明显缺陷的对手池最大化 bb/100，调出来的是**剥削策略**，
不是好策略——换个对手池结论就会变。PRD 对 FR-11 的验收写的是
「统计落在**合理区间**」，那是「像个正常玩家」的标准。

按这个标准看：真实扑克的 WTSD 是 25–30%，而 `bet=0.35` 也才到 36.6%。
**说明还有别的东西让 WTSD 偏高**（多半是翻后跟注阈值本身，那是风格参数的事，
不是收缩比例的事）。那是下一段该查的，不是靠继续扫这个参数能解决的。
