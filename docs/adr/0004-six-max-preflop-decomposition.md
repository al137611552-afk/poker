# ADR-0004：六人桌翻前范围——按位置分解成两人子博弈

- 日期：2026-08-17（2026-08-18 修订：补上简化 ③，见文末「修订」）
- 状态：已接受（实现完成：`preflop_chain.py` + 离线范围表）
- 承接：ADR-0003（翻前树 + 翻后压缩模型）

## 背景

ADR-0003 立的路线是「自解抽象翻前树」，单挑已经能解。推到六人桌时撞上规模：

| | 节点数 | 纯 Python 向量 CFR |
|---|---|---|
| 单挑 100bb（含跛入、开到 4bet） | 40 | 1500 次迭代 75 秒，可利用度 0.0026 |
| **六人 100bb（同样的动作集）** | **623,070** | 跑不动 |

每个决策节点带 169 个信息集，每次遍历要对每个终局做矩阵乘向量。六人树的终局有 33 万个，
一次遍历就要几分钟——迭代上千次没有可行性。

## 备选方案

| 方案 | 内容 | 结论 |
|---|---|---|
| A 裁剪整树 | 关掉跛入、只留一层再加注，六人树降到约 5 千节点，一次解出全桌 | 未采用：动作集被砍到只剩「开牌 / 3bet」，4bet 层没了，而 4bet 恰恰决定强牌怎么打 |
| B **按位置分解** | 每个位置单独解「我开牌 vs 身后某一家」的两人子博弈，再把身后各家的结果合成开牌 EV | **采用** |

选 B 的理由：**六人桌的翻前局面绝大多数本来就是两人局面**——一个人开牌、一个人应对。
分解之后每个子博弈只有十来个节点，动作集反而能保留得比 A 更细（3bet、4bet、全下都在）。
代价是多人底池要另行处理（见下）。

## 决策

### 1. 子博弈怎么切

树支持从中途切一段（`SubgameConfig`）：显式给出两人各自已投入的钱、**无主的死钱**、
谁先说话、谁翻后最后说话，以及「进来时已经加注过几次」。于是「CO 已开牌到 2.5、BB 应对」
就是一棵 6 决策 / 12 终局的小树，BB 的加注按 3bet 计价、CO 还能 4bet。

死钱的账要平：不在场的人留下的盲注与前注**一分不少地进底池、一分不多地算给谁**。
`TableConfig.walk_value` 与子博弈弃牌终局算出来的必须是同一个数，这条有测试守着。

### 2. 合成公式

设开牌者 p 身后依次是 q₁…q_k，各自的聚合弃牌频率 f₁…f_k：

```
EV_开牌(i) = Πf_m · W + Σ_m (Π_{l<m} f_l)(1 − f_m) · EV_继续_m(i)
```

`EV_继续_m(i)` 取自子博弈里「防守者没弃牌」的那几个分支。**合并必须在归一化之前做**：
每个分支的除数（对手在该分支里还剩多少组合）按牌类不同，先除再加权会引入误差。
为此求解器把分子分母分开存（`BranchValue`）。

### 3. 外层怎么收敛

外层对「开牌 / 弃牌」跑 CFR+（与 `pushfold.py` 同一套遗憾匹配），每轮用**平均**开牌范围
重解全部子博弈。**这不是对合成博弈的收敛性证明**，是「迭代最佳应对 + CFR+ 平滑」；
判据是范围本身还变不变（`TableSolution.max_change`，写进产物）。

### 4. 离线算、随包分发

解一次整桌十几分钟，所以与翻前权益表同样处理：`scripts/build_preflop_ranges.py` 离线生成
JSON，`holdem.preflop_ranges` 只负责查表。**产物里连参数一起存**（兑现系数、开牌尺度、
扫了几轮、最后一轮变动多少）——脱离参数的范围表没法复现也没法审计，将来兑现系数校准过
（ADR-0003）要能一眼看出手上这张是哪套算的。

## 已知简化（都是抽象，不是疏漏）

1. **只有第一个不弃牌的人继续**。冷跟之后再有人挤压、多人底池，都不建模——多人终局要在
   三个以上对手的联合分布上积分，那是另一码事。方向：使范围偏松。
2. **弃牌的人不带走牌**。各家的弃牌频率按聚合值处理，不做「他弃牌所以他手里没有大牌」的
   条件化修正。
3. ~~**防守者不用担心身后**~~。**2026-08-18 已补上**，见文末「修订」。
4. **开牌尺度固定 2.5bb**，不按位置变化。

① ② 会让解偏离真正的六人均衡，方向已知；等兑现系数校准之后再评估要不要补。

## 验证

没有「精确解」可比，所以守三件事，都有测试：

1. **账要平**：死钱、白得价值、弃牌代价三处口径一致；合成出的 EV 必须落在「全弃白得」与
   「各家没弃牌时的 EV」构成的凸包里，权重之和恰为 1。
2. **方向要对**：身后的人越少开得越宽——`UTG ≤ HJ ≤ CO ≤ BTN` 是产物本身的回归测试。
3. **子博弈解到位**：每个子博弈的可利用度随产物一起存下来，低于阈值才算数。

外加量级对照（不作基准，只防跑偏）：枪口位开牌一两成、按钮四成上下。

## 修订（2026-08-18）：补上简化 ③「防守者不用担心身后」

### 为什么改这条

A 档校准（Slumbot 实测 2000 手）顺带更正了一个归因：此前把「六人桌大盲防守偏宽」算在
兑现模型头上，但实测**单挑**下我们的大盲反而比 Slumbot 弃得更多（25% vs 16%）。既然
单挑不宽、六人宽，病根就不在兑现系数，而在六人桌特有的抽象——简化 ③。

道理也直白：只在两人子博弈里想事情，**跟注就没有后顾之忧**。真实六人桌里跟注之后
身后每个人都可能挤压（squeeze），把跟注者夹在中间，所以真解里靠前的位置几乎不冷跟，
是「3bet 或弃牌」。我们的表却让 HJ 面对 UTG 开牌冷跟 19%——高出公开解一个数量级。

### 怎么建模

不进树（树里只有两个人，第三方进不来），而是挂在**「防守者跟注、行动结束」那个终局**上：

```
收益 = (1 − S) · 原来的翻后模型  +  S · 「被挤压」的收益
```

- **S 怎么来**：q 身后每个人 r 的挤压频率取他**面对同一个开牌的 3bet 频率**
  × `SqueezeModel.frequency_scale`（默认 0.6——面对「开牌 + 一个跟注」的挤压比单纯
  3bet 少），再按「谁先挤压」链式合成。用的是**上一轮**的 3bet 频率（同一轮里身后
  那几家还没算到），与外层用平均范围重解是同一个套路；第一轮等于不建模挤压。
- **被挤压之后怎么打**：再切一段子博弈（`_facing_squeeze`），q 可以弃/跟/4bet/全下，
  照常 CFR+ 解——所以强牌打得回去，弱牌该弃就弃，不是拍一个惩罚系数。
- **开牌者按弃牌处理**：他投的 `open_to` 全部变成死钱，由 q 与挤压者去争。账因此是平的：
  桌上每一分钱要么在两人的 `posted` 里，要么在 `dead_money` 里。

### 代价：这条支路不再是两人零和

底池有一部分被第三方拿走，所以带挤压的子博弈里 `player_ev` 之和**小于**死钱，
差额就是挤压者的所得。这是模型的应有之义，不是账没平——测试守的是这条不等式。

### 效果（六人 100bb，8 轮扫描，23.4 分钟）

| | 冷跟（旧 → 新） | 开牌（旧 → 新） | 公开 GTO 开牌 |
|---|---|---|---|
| HJ 面对 UTG | 19% → **6%** | 23.7% → 18.9% | 21–23% |
| CO 面对 UTG | 19% → **7%** | 29.6% → 25.5% | 27–29% |
| BTN 面对 CO | 24% → **13%** | 41.3% → 38.5% | 42–45% |
| SB 面对 BTN | 28% → **20%** | 38.8% → 38.8% | — |
| **BB 面对 BTN** | 56% → **54%** | UTG 20.8% → 14.8% | 17–19% |

- **方向完全对**：冷跟塌陷、3bet 频率几乎不动（8%→6%、12%→11%），正是真解里
  「身后有人就 3bet 或弃牌」的结构；**大盲身后没人，纹丝不动**（SB 开 vs BB 一模一样）。
- **幅度过头**：开牌范围现在比公开解**紧 2–4 个百分点**（此前是松 2–3 个）。
- 收敛还更好了（最后一轮变动 0.0023，之前 0.0053）。

### 幅度为什么会过头（新的已知简化，按嫌疑大小排）

1. **被挤压时开牌者一律弃牌**——那是他的**下界**（跟或 4bet 只会更好）。开牌者因此
   在「被冷跟」这条支路上被高估了损失，开牌范围被压得偏紧。要修得建三人子博弈，
   那正是本 ADR 一开始就排除掉的多人积分。
2. **挤压频率取自 3bet 频率 × 0.6**，那个 0.6 是假设，不是测量值。
3. q **3bet 之后**身后再有人冷 4bet，不建模（频率低一个量级）。
4. 挤压者只被建模成「加注」；他冷跟造成的多人底池仍按简化 ① 处理。
5. 挤压尺度固定在 3bet 梯子上再加 1bb，不按人数/位置变化。

**不按公开图表回调 0.6**：那等于拿别人的表当真值，与本项目「正确性靠可利用度自证、
公开图表只作量级对照」的口径相悖（ADR-0003 里踩过 HoldemResources 串行错值的坑）。
真校准仍走 ADR-0003 的 B 档——用实解反推，那时连同兑现系数一起定。
